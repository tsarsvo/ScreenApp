# Безопасность Kadr

## Поддерживаемые версии

Исправления безопасности выходят только для **последней версии** — установленный Kadr обновляется сам
(меню значка в трее → «Обновить до vX» или «Проверить обновления» в настройках).

| Версия | Поддержка |
|:--|:--:|
| последняя из [Releases](https://github.com/tsarsvo/ScreenApp/releases/latest) | ✅ |
| более старые | ❌ — обновитесь |

## Как сообщить об уязвимости

Пожалуйста, **не создавайте публичный issue**. Сообщите приватно:
**Security → [Report a vulnerability](https://github.com/tsarsvo/ScreenApp/security/advisories/new)**.

Опишите, что можно сделать и как это повторить (версия Kadr и Windows, шаги). Ответ — в течение нескольких дней;
после исправления выйдет новая версия, а в описании релиза будет указано, что закрыто.

## Как устроена защита

- **Автообновление** скачивает установщик только по `https` и только с адресов GitHub (в том числе после
  перенаправлений) и запускает его, **только если совпала контрольная сумма SHA-256**, опубликованная GitHub
  для этого файла. Без контрольной суммы Kadr ничего не устанавливает сам, а открывает страницу релиза.
- **Сеть**: Kadr обращается только к `api.github.com` (проверка обновлений раз в сутки — можно выключить
  в настройках) и к файлам релизов GitHub. Скриншоты, записи и настройки никуда не отправляются.
- **Права администратора** — только если включить их тумблером в настройках: Windows каждый раз спрашивает
  разрешение, в системе ничего не прописывается.
- **FFmpeg** (запись повтора) — официальная LGPL-сборка, при сборке проверяется её `sha256`; процесс FFmpeg
  привязан к Kadr и завершается вместе с ним.

## Автоматические проверки

- **CodeQL** (набор правил *security-and-quality*) — Python-код и сценарии GitHub Actions: на каждый PR,
  пуш в `main` и раз в неделю.
- **Dependabot** — уведомления об уязвимых зависимостях и еженедельные обновления.
- **ruff** с правилами безопасности (bandit) — на каждый пуш и PR.
- **Сквозная проверка** настоящего `Kadr.exe` на Windows перед каждым релизом.
